# floor-takeoff-harness

실제 공공 인테리어 공사 도면으로 **AI 바닥재 물량산출**을 시키고, 같은 모델로 지시·도구·입력을 바꿔 6번 개선한 실험 기록입니다.
채점은 사람이 센 값이 아니라 **PDF 안에 남아 있는 CAD 벡터로 방 19개를 직접 측정한 값**으로 했습니다.

- 결과 페이지: https://floor-takeoff-harness.vercel.app
- 대상: 대한변호사협회 신회관 인테리어 공사(2022) 입찰공고 공개 자료 — 기본도면 PDF 133장, 공내역서
- 범위: 바닥 마감 7종(DE·DT·CT) 면적, 걸레받이 길이

## 결과

| 버전 | 바꾼 것 | 방 단위 평균 오차 | ±5% 이내 | 합계 오차(도면 기준) |
|---|---|---:|---:|---:|
| v1 | 도면 4장 주고 "물량 산출해줘" | 채점 불가(방별 근거 없음) | – | −2.6% |
| v2 | 실별 표 형식, 근거·신뢰도 기재 | 16.3% | 6 / 19 | −15.4% |
| v3 | 입력 추가: 치수 도면 + 고해상도 4분할 타일, 적힌 숫자만 | 14.3% | 4 / 19 | −5.7% |
| v4 | 견적 실무 규칙 R1~R7 (안목, 기둥 공제, 이중계산 금지, 정미량, 층별 검산) | 8.8% | 8 / 19 | −4.6% |
| v5 | 검토자 에이전트가 도면과 대조 (방 정확도 변화 없음, 규칙 위반·걸레받이 정리) | 8.8% | 8 / 19 | −8.5% |
| v6 | 검증에서 찾은 오차 패턴(창측 555mm 띠) 규칙 추가 | **4.3%** | **13 / 19** | −3.4% |

v6의 가장 큰 개선은 **창가 회의실·임원실 8곳이 체계적으로 10~19% 작게 나오던 원인**을 찾은 것입니다. 실 깊이 치수선 뒤에 창까지의 띠(555/450/439mm, FCU 박스 구간)가 따로 적혀 있었고, AI가 이 띠를 빠뜨렸습니다.

## 구조

```
harness/
  score.py          채점기: AI 결과를 ① CAD 벡터 실측 ② 공내역서 두 기준과 비교
  make_xlsx.py      내역서 양식 산출근거서(엑셀) 생성
  build_page.py     결과 페이지 빌드 (site/ 템플릿 + 데이터)
  build_vercel.py   배포용 단독 페이지(dist/) 생성
tests/              채점기·엑셀 회귀 테스트 (pytest)
  scores.json       버전별 채점 결과
runs/v1 ~ v6/
  prompt.txt        그 버전의 지시문 (작업자는 정답·내역서에 접근 금지)
  output.json       AI 산출 결과 — 실별 면적, 치수 출처와 계산식, 신뢰도, 검토 기록
truth/
  boq_truth.json        공내역서 수량 (바닥재 9종, 걸레받이)
  vector_reference.json CAD 벡터 실측 — 방별 안목 면적, 둘레, 축척 검증 기록
scripts/              도면 PDF → 입력 이미지, 벡터 실측, 3D 장면 추출 (PyMuPDF·OpenCV)
site/                 페이지 소스, 3D 장면(scene.json), 오버레이 이미지
dist/                 Vercel 배포본
```

## 방법

1. **입력**: 마감 평면도 3장, 치수 평면도 3장, 자재표 1장. v3부터 각 도면을 165dpi 4분할 타일로 함께 제공.
2. **작업자**(Claude Sonnet, 서브 에이전트): 정답을 보지 못한 상태에서 실별로 면적을 산출하고, 행마다 어느 타일의 어떤 치수를 읽었는지 기록.
3. **검토자**(v5): 층별 면적 검산, 저신뢰 실 재판독, 규칙 위반 제거.
4. **채점기**: 
   - CAD 벡터 실측 — PDF의 레이어(wall, WID, COR, CONW, 창호, 문틀)만 래스터화해 실 이름 위치에서 flood fill. 축척은 층마다 치수 4곳으로 교차 확인(0.07% 이내).
   - 공내역서 — 자재 종류별로 대조 (내역서 코드 번호 체계가 도면 범례와 달라 코드별 대조는 불가).
5. **개선**: 체계적으로 틀린 방을 묶어 원인을 찾고 규칙으로 되돌림.

## 찾아낸 것

- 바닥재 합계 1,323㎡ ≈ 같은 내역서의 바닥 바탕정리 1,324㎡ → 내역 수량은 정미량, 할증은 일위대가에 있는 것으로 보임
- 도면 범례에는 카펫 CT-01~03뿐인데 내역에는 CT-01~05 → 번호 체계 불일치
- 규격 불일치: DE-01(내역 300×300 / 도면 450×450), DT-01(내역 450×450 / 자재표 600×600)
- 도면에서 측정 가능한 코드 면적 1,197.6㎡ vs 내역 1,323㎡ → 차이 125㎡의 원인 후보(무코드 실, 미표기 구역, 창측 띠·단상 처리)

## 한계

- 걸레받이는 내역 대비 −40%로 아직 못 풀었습니다.
- 공사 1건, 버전마다 1회 실행입니다.
- v6 규칙은 검증 세트에서 찾아 같은 세트로 평가했으므로 4.3%는 낙관적입니다.
- 실측 기준 자체도 10㎡ 넘는 방은 ±1~2%, 작은 방은 더 큰 오차가 있습니다.
- 열린 공간(복도·사무실 연결부)의 코드 경계는 기하학적 분할이라 ±10~20㎡ 오차가 있을 수 있습니다.

## 테스트

`pytest -q` — 17개. 정답 데이터 합계, 이름 정규화 규칙, 버전별 점수가 공개한 숫자(`scores.json`)와 같은지, ±5% 판정을 반올림 전 값으로 하는지(반올림하면 13이 아니라 14가 됨), 엑셀 '실별 산출서' 합계가 AI 산출과 같은지 확인합니다. 푸시마다 GitHub Actions에서 돕니다.
